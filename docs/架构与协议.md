# 架构与协议

面向要改代码的人。普通使用看 [README](../README.md) 就够了。

---

## 1. 三个部件

| 部件 | 位置 | 运行环境 | 职责 |
|---|---|---|---|
| Zotero 插件 | `plugin/` → `.xpi` | Zotero 7–10（bootstrap 型插件） | 取 PDF 文字、分块、拼 prompt、生成文档、UI |
| 本地中转服务 | `bridge/server.js` | Node ≥ 18，零依赖 | 任务队列、长轮询、状态页、静态托管油猴脚本 |
| 油猴脚本 | `bridge/deepseek-bridge.user.js` | Tampermonkey + chat.deepseek.com | 把 prompt 打进网页、抓回答、回传 |

只有插件会主动发 HTTP；三者之间**没有共享内存**，全部走 `http://127.0.0.1:8765`。

```
插件 ──POST /v1/translate──────> 中转服务 ──GET /v1/bridge/next (长轮询)──> 油猴
     <──200 {translation}──────           <──POST /v1/bridge/result────────
```

## 2. 中转服务 HTTP 协议

基址 `http://127.0.0.1:8765`，只监听回环地址。所有响应都是 JSON（状态页除外），UTF-8。

### 2.1 `POST /v1/translate`（插件调用）

阻塞式：一直等到浏览器端返回译文，或超时。

```jsonc
// 请求
{
  "prompt": "你是一名专业的学术文献翻译引擎……\n<<<\n待翻译文本\n>>>",
  "targetLang": "简体中文",     // 仅用于日志
  "timeoutMs": 240000           // 可选，默认 240000，夹在 30s–900s
}

// 200 成功
{ "ok": true, "translation": "……译文……", "engine": "deepseek-web" }
```

| 状态码 | 含义 | 典型 error |
|---|---|---|
| 200 | 成功 | — |
| 400 | 缺 prompt | `缺少 prompt 字段` |
| 403 | 来源不可信 | `不允许的来源：https://…` |
| 503 | **浏览器端未连接**（25 秒内无心跳） | 提示装油猴 / 打开标签页 |
| 504 | 浏览器端报错或超时 | 透传浏览器端错误信息 |

> 503 是"快速失败"：油猴没连上时不该让插件白等 4 分钟。

### 2.2 `GET /v1/bridge/next?wait=25`（油猴调用）

长轮询取任务。有任务立刻返回；没有就挂起最多 `wait` 秒（1–60，默认 25），然后返回 `job: null`。

```jsonc
{ "ok": true, "job": { "id": "uuid", "prompt": "……", "targetLang": "简体中文" } }
{ "ok": true, "job": null }
```

取到即视为"派发"，任务状态 `pending → running`，服务端同时启动超时计时器。

### 2.3 `POST /v1/bridge/result`（油猴调用）

```jsonc
{ "id": "uuid", "ok": true,  "text": "……译文……" }
{ "id": "uuid", "ok": false, "error": "页面结构变了" }
```

返回 `{ok:true, accepted:true}`；任务已超时/不存在则 404。**空译文按失败处理**。

### 2.4 其他

| 接口 | 用途 |
|---|---|
| `POST /v1/bridge/heartbeat` | 心跳，`{ok:true,pending,running}`；/next 和 /result 也会顺带刷新心跳 |
| `POST /v1/bridge/log` | 油猴把 `console.log` 转发到服务端终端，`{message}` |
| `GET /v1/health` | 状态页和"连接自检"用，见下 |
| `GET /` | 深色状态页，2 秒轮询 /v1/health |
| `GET /deepseek-bridge.user.js` | 托管油猴脚本，方便一键安装 |

`GET /v1/health` 返回：

```jsonc
{
  "ok": true, "version": "0.1.0", "pid": 1234, "uptimeSec": 42,
  "userscript": { "connected": true, "lastSeenAgoMs": 1200 },
  "queue": { "pending": 0, "running": 1 },
  "stats": { "done": 12, "failed": 0 },
  "lastError": ""
}
```

### 2.5 安全边界

- 只 bind `127.0.0.1`，不对外网开放；
- POST 校验 `Origin`：无 Origin / `null` / 浏览器扩展协议 / 本机地址 / `https://chat.deepseek.com` 放行，其他一律 403（防其它网页 CSRF 式刷你的额度）；
- 请求体上限 1 MB。

## 3. 任务生命周期

```
                 ┌──────────┐  /v1/bridge/next   ┌──────────┐  result ok   ┌──────┐
POST translate ─>│ pending  │ ─────────────────> │ running  │ ───────────> │ done │
                 └──────────┘                    └──────────┘              └──────┘
                      │                               │
                      │ 超时 / 浏览器报错              │ 超时
                      └──────────────┬────────────────┘
                                     v
                                  ┌───────┐
                                  │ error │
                                  └───────┘
```

- 超时默认 240 秒（可被请求里的 `timeoutMs` 覆盖）。超时任务从队列移除并让 `/v1/translate` 返回 504。
- 任务**不重试**：重试策略在上层（插件对每块最多重试 2 次，间隔 1.5s/3s）。
- 队列是 FIFO；多个 Zotero 请求会排队，油猴一次只处理一个（浏览器只有一个输入框）。

## 4. 油猴脚本怎么操作网页

### 4.1 主循环

```
每 10s 心跳
loop:
  GET /v1/bridge/next?wait=25
  有任务 → ask(prompt) → POST result → 回到 loop
  无任务 → 立刻再轮询（长轮询本身就是等待）
  连接失败 → 徽标变红，5 秒后重试
```

### 4.2 发送一条消息

1. 找输入框：可见的 `textarea` / `[contenteditable=true]` 中**面积最大**的那个；
2. 写值：`textarea` 走原型链 `value` setter + 派发 `input`/`change`（React 受控组件必须这样）；`contenteditable` 退化为 `execCommand('insertText')`；
3. 点发送：从输入框向上找 7 层父节点，在每层里找 `button`/`[role=button]`：
   - 优先 `aria-label`/`title`/文本含「发送 / send」；
   - 否则取"带 svg、且文案不含深度思考/联网搜索/上传/附件/语音/登录"的**最后一个**（发送键通常在输入框右侧最末）；
4. 兜底：派发 `Enter` 的 keydown/keypress/keyup；
5. 校验：5 秒内"回答块数量 +1"或"输入框已清空"才算发出去，否则换另一种方式再试一次，还不行就报错回传。

### 4.3 判断"回答写完了"

这是最容易出问题的地方，用了三层：

1. **MutationObserver** 监听最后一个回答块（`.ds-markdown`）及 `document.body`，DOM 一变就检查——**不受后台标签页定时器节流影响**；
2. 用「停止生成」按钮是否存在判断是否还在生成；一旦它消失且文本 1.6 秒没变化 → 完成；
3. 如果从头到尾没检测到「停止生成」（说明按钮选择器失效），退化为"文本 6 秒没变化 → 完成"，避免长段落被截断。

`innerText` 与发送前的"基线文本"比较，避免把上一条回答误当新回答；超时则返回已有文本。

### 4.4 会话管理

同一对话连续翻译 `CONFIG.newChatEvery`（默认 6）段后，尝试点「新对话」。找不到按钮就继续在当前会话里翻——**绝不通过改 `location` 来"新开对话"**，那会中断正在进行的任务。

### 4.5 改版了怎么修

改 `bridge/deepseek-bridge.user.js` 顶部：

```js
const CONFIG = { newChatEvery: 6, stepTimeoutMs: 180000, idleStableMs: 1600, ... };
const SELECTORS = {
  input:  'textarea, [contenteditable="true"]',
  answer: '.ds-markdown, [class*="ds-markdown"], [class*="markdown"]',
  newChat: '新对话,新的对话,开启新对话,New chat',
  stop: /停止生成|停止回答|Stop generating|Stop/i,
  toggleIgnore: /深度思考|联网搜索|上传|附件|…/i
};
```

改完在 Tampermonkey 里刷新脚本、刷新页面即可。调试打开 `CONFIG.debug`，日志会同时进浏览器控制台和黑窗口。

还需要注意：**「深度思考」「联网搜索」必须处于关闭状态**（脚本只会关掉它"确定处于开启状态"的开关，判断不确定时不动手，以免误开）。用前确认一下页面上的这两个按钮是灰的。

### 4.6 后台标签页节流

Chrome 对隐藏超过 5 分钟的页面会把定时器压到约 1 次/分钟。脚本靠 MutationObserver 规避了大部分问题，但**长任务仍建议把 DeepSeek 窗口保持可见**；徽标在页面隐藏时会显示「待命中（标签页在后台）」。

## 5. 插件侧流水线

`bootstrap.js` → `translateSelectedItems()` → `runFullTranslation()` → 每个附件 `translateOneAttachment()`：

| 阶段 | 调用 | 说明 |
|---|---|---|
| 1. 取文字 | `Zotero.PDFWorker.getFullText(itemID)` | 返回 `{text, extractedPages, totalPages}`；失败则回退读 `.zotero-ft-cache` |
| 2. 规整 | `core.normalizeText()` | 去页码/页眉、中文跨行拼接、英文连字符断词修复、标题行独立成段 |
| 3. 分块 | `core.splitParagraphs()` + `core.buildChunks()` | 按句子边界切，块 ≤ `chunkSize`，超过 `maxChunks` 截断并标记 |
| 4. 翻译 | `core.buildPrompt()` → `translatePrompt()` | 每块一条 prompt，最多重试 2 次；连续 3 块失败则中止 |
| 5. 组装 | `core.buildDocx()` / `buildHtml()` | DOCX 由内置最小 OOXML + 无依赖 ZIP 写入器生成（store 模式，Word/WPS 均可） |
| 6. 导入 | `Zotero.Attachments.importFromFile({file, parentItemID, fileBaseName, title})` | 自动复制进 storage，并设为子附件 |

**进度与取消**：`Zotero.ProgressWindow`（`closeOnClick:false`）+ 每块更新 `ItemProgress`；取消靠全局 `DSWT.state.cancel`，由「工具 → 取消…」置位，每块开始前检查。

**输出格式**：`outputFormat = docx | html | both`。docx 生成失败会自动回退 html，不会让整个任务失败。

### 5.1 划词翻译（不走全文流水线）

触发点是阅读器的 `renderTextSelectionPopup` 事件。每次弹窗渲染：

1. 清掉同一 `doc` 里残留的 `.dswt-box`（拖选会反复重建弹窗）；
2. 用 `append(box)` 把结果容器**插进弹窗本身**（不另开浮窗）；
3. 递增 `DSWT.state.selectionSeq` 作为令牌，旧请求返回时令牌对不上就丢弃结果（避免慢响应覆盖新选区）；
4. 若开启 `selectionAuto` 且文本 ≤ 600 字符 → 300ms 防抖后自动翻译；否则只画一个「译」按钮。

判定单词：`looksLikeWord()` —— 无空格、≤ 40 字符、纯拉丁字母（允许连字符/撇号/点）。命中则用 `core.buildDictPrompt()` 拿「词性|释义」多行，`core.parseDictResult()` 容错解析（容忍 markdown 列表、编号、加粗、代码块、全角冒号）；解析不出义项就回退成普通译文，绝不因为格式问题报错。

结果按 `word|lang|text` 缓存在 `DSWT.state.selectionCache`（上限 200 条），重复选中同一个词直接出结果。

## 6. 翻译后端与扩展

`translatePrompt()` 按 `provider` 分发：

- `web` → `callBridge()`：POST `/v1/translate`，拿 `data.translation`；
- `openai` → `callOpenAI()`：POST `{apiBase}/chat/completions`，标准 OpenAI 协议，`Authorization` 有 key 才加（兼容本机 Ollama）。

**加一个新后端**只要在 `translatePrompt()` 里加一个分支，返回字符串即可（如 Gemini、Claude、自建代理）。Prompt 由 `core.buildPrompt()` 统一生成，各后端共用。

## 7. 偏好键

`extensions.zotero.deepseekweb.*`，全部在 `plugin/prefs.js` 里给了默认值。
数值项（chunkSize / timeoutSec / maxChunks）**故意用字符串存**，避免 `preference` 绑定写入时 pref 类型不匹配（绑定写入的是字符串）。

设置面板 `content/preferences.xhtml` 是 Zotero 原生 `PreferencePanes` 片段，字段靠 `preference="完整键名"` 自动双向绑定，**不需要额外脚本**；只有「测试中转服务连接」按钮调 `Zotero.DeepSeekWebTranslate.testConnection()`。

## 8. 已知取舍

- **不做 PDF 重排**：没有 PDF 排版引擎，输出 docx/html；要 PDF 就再导出一次。
- **只读文字层**：扫描版必须先 OCR。
- **逐段串行**：网页版只有一个输入框，并行没意义；API 模式理论上可以并发，目前也没做（避免触发限流）。
- **块级对齐，不是句级**：文档里一块原文对应一块译文；块内部保留段落换行，但句级对齐做不到（除非每句一次请求，太慢）。
- **不支持 EPUB/网页快照**：`getStructuredDocumentText` 虽然能吃这些格式，但返回结构在不同版本间不稳定，当前只处理 PDF 和纯文本附件。
